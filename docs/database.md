# Database

PostgreSQL 16 is the durable source of truth (ADR-005). Redis holds only
ephemeral data.

## Migrations

- Location: `db/migrations/NNNNNN_name.up.sql` + `NNNNNN_name.down.sql`
  (golang-migrate format), embedded into Go binaries via `db/embed.go`.
- Apply: `make migrate` (or `go run ./go/cmd/migrate up`); in Docker the
  one-shot `migrate` service runs before any application service starts.
- Roll back one: `make migrate-down`. Status: `make migrate-status`.
- Recovery from a failed migration: fix the cause, then
  `go run ./go/cmd/migrate force <last-good-version>`.
- No ORM auto-sync anywhere. Every schema change is a reviewed SQL migration
  with a working down migration; CI applies all migrations, rolls them all
  back and re-applies them (`go/dbmigrate` integration test).
- Migrations must be forward-safe on a non-empty database: add columns as
  nullable or with defaults, backfill in batches, then tighten constraints in
  a later migration.

## Conventions

- snake_case identifiers; `id uuid PRIMARY KEY` (UUIDv7 generated by the
  application; `gen_random_uuid()` default as a fallback).
- `created_at timestamptz NOT NULL DEFAULT now()`; mutable tables also have
  `updated_at` maintained by the `set_updated_at()` trigger.
- Chip amounts are `bigint`. No `numeric`/`float` for chips.
- Append-only tables (ledger, audit log, game events) use the
  `reject_mutation()` trigger to block UPDATE/DELETE.
- Enumerations are `text` with `CHECK` constraints (easier to evolve than
  PostgreSQL enum types).
